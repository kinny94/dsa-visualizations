Algorithm

    

      
• key < val → recurse LEFT

      
• key > val → recurse RIGHT

      
• key == val → four sub-cases:

      

        
①  left == null → return right

        
②  right == null → return left

        
③  2 children → find min of right subtree, copy its value in, recursively delete it from right

      

    

    

      
Why inorder successor?

      

        We need a replacement v such that left subtree < v < right subtree. The smallest value in the right subtree is v: already > everything in the left subtree, and ≤ everything else in the right. Equivalently, the largest value in the left subtree works (inorder predecessor).
      

    

    

      
The copy-and-delete trick

      

        Instead of unhooking and re-stitching the successor node, copy its value into the target node, then recursively delete the successor from the right subtree. The successor has at most a right child (it's the leftmost of its subtree), so the recursive delete hits an easy case.
