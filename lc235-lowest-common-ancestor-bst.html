Algorithm

    
node = root;
while (node != null) {
    if (node.val < p.val &&
        node.val < q.val) {
        node = node.right;
    } else if (node.val > p.val &&
               node.val > q.val) {
        node = node.left;
    } else {
        return node;  // LCA
    }
}

    

      
The three verdicts

      

        
① both < node → go left

        
② both > node → go right

        
③ split OR one equals node → LCA

      

    

    

      
Why the split point IS the LCA

      

        If p and q sit on opposite sides of a node, both subtrees contain exactly one of them. No lower node contains both. The split point is the deepest common ancestor.
      

    

    

      
Why one-equals-node also exits

      

        If node.val == p.val, then q is somewhere in node's subtree (both less → above, descended here) — so node is an ancestor of q, and an ancestor of itself. Nothing lower contains p.
      

    

    

      
vs LC 236 (binary tree)

      

        LC 236 can't descend by value comparison — it needs post-order propagation, O(n). LC 235 exploits the BST invariant for O(h).
