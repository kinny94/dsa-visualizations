LC 510 — Inorder Successor in BST II

No root — just p with a .parent pointer. Two cases: (A) p.right exists → leftmost of p.right; (B) else → climb up via .parent while we came from a right child; the first "came-from-left" ancestor is the answer. Tree = [20,10,30,5,15,25,35].

Algorithm

    
if (p.right != null) {
    // Case A: leftmost of p.right
    cur = p.right;
    while (cur.left != null) {
        cur = cur.left;
    }
    return cur;
}
// Case B: climb while coming from right
cur = p;
while (cur.parent != null
       && cur == cur.parent.right) {
    cur = cur.parent;
}
return cur.parent;  // may be null

    

      
Why "came from left" ancestor?

      

        Inorder visits an ancestor after its entire left subtree. If p lives in ancestor A's left subtree, A comes right after p (ignoring everything between). If p is in A's right subtree, A was already visited before p.
      

    

    

      
Climb past the root

      

        If the loop climbs past the root (all ancestors came from right), cur.parent is null — return null. That's the "p is the maximum" case.
      

    

    

      
vs LC 285

      

        LC 285 has root, no parent pointer → descend. LC 510 has parent, no root → local analysis + climb. Both O(h) time, O(1) space.
