The two-iterator idea

    

      Inorder on a BST yields sorted ascending values. Reverse inorder yields descending. Simulate sorted array + two pointers without building the array: two stacks, each lazily produces the next value from one end.
    

    

      
Advance rule

      

        sum == k → found.

        sum < k → need a bigger left value, advance L (next inorder).

        sum > k → need a smaller right value, advance R (next reverse inorder).

        Stop when l == r (pointers crossed).
      

    

    

      
Stack states

      

        Each stack holds "nodes whose values haven't been yielded yet." Top of stack = next to yield. The pushLeft / pushRight helpers walk one chain; nextLeft / nextRight advance by pushing the appropriate subtree then popping.
      

    

    

      
Why O(h) space

      

        Each stack holds at most one chain — the current ancestry — never more than O(h) nodes. HashSet version is O(n) because it stores every visited value.
