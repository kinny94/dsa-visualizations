LC 99 — Recover Binary Search Tree

Inorder on a valid BST is strictly sorted — two inversions (or one) betray the swapped pair. Lock first on the first inversion's prev; overwrite second with every inversion's curr. Tree = [3,5,4,1,null,null,2]; swapped pair = (5, 2).

Algorithm

    

      
Inorder walk. At each visit:

      

        
• if prev != null && prev.val > node.val:

        

          
- if first == null → first = prev

          
- second = node

        

        
• prev = node

      

      
At end: swap first.val ↔ second.val.

    

    

      
Why first/last asymmetry?

      

        A swap creates a "too-big" value floating LEFT (shows up in the prev of the first inversion) and a "too-small" value floating RIGHT (shows up in the curr of the last inversion). Adjacent swap = both fall into one inversion; non-adjacent = they split across two.
      

    

    

      
Swap values, not nodes

      

        The problem forbids changing structure. We only overwrite the two .val fields — pointers stay untouched.
