LC 333 — Largest BST Subtree

Post-order with a 4-field bundle per subtree: (isBST, size, min, max). At each node, combine the two children's bundles and check L.max < node.val < R.min. Track global best. Input: tree [10, 5, 15, 1, 8, null, 7].

Algorithm

    

      
post(node):

      

        
• null → (BST, size=0, min=+∞, max=-∞)

        
• L = post(node.left)

        
• R = post(node.right)

        
• if L.isBST ∧ R.isBST

        
  ∧ L.max < node.val < R.min:

        

          
- size = L.size + R.size + 1

          
- mn = min(L.min, node.val)

          
- mx = max(R.max, node.val)

          
- best = max(best, size)

          
- return (BST, size, mn, mx)

        

        
• else return (notBST, …)

      

    

    

      
Why ±∞ for null?

      

        A missing child must always pass the parent's check. We return min=+∞, max=−∞ so L.max < node.val and node.val < R.min both trivially hold — the null side can't disqualify the subtree.
      

    

    

      
Why need min AND max?

      

        The whole left subtree must be < node.val — so we need the biggest value anywhere below-left (L.max). Mirror for right. Comparing only node.left.val < node.val fails when a grandchild violates (e.g. 10 with left=5, 5.right=15 — locally 5<10 passes but 15 lives in 10's left subtree and 15>10).
